# Мʼясний Барон — сайт + Telegram-бот

## Структура
```
meat-baron/
├── index.html      ← увесь сайт: верстка, каталог, кошик, оформлення
├── catalog.js      ← прайс, правила рахунку і точки: читають обидва
├── sw.js           ← service worker (офлайн і кеш)
├── manifest.json   ← PWA
├── photo/          ← фото товарів
├── server.js       ← API прийому замовлень + Telegram-бот
├── package.json
└── data/           ← база замовлень, у git не потрапляє
```

**Ціни й точки правимо лише в `catalog.js`.** Щоб увімкнути точку —
постав 1 у третьому стовпці `SHOPS_ALL`. Браузер підключає його тегом
`<script>`, сервер робить `require`. Сума замовлення рахується на
сервері за цим списком, а не приймається з браузера — інакше її можна
було б підмінити. Якщо клієнт надіслав іншу суму (застарілий кеш після
зміни цін або підробка), оператор побачить у чаті попередження.

Сайт лежить **у корені**. Другої копії немає — це навмисно.
Раніше поруч була тека `public/` з окремим `index.html`, і дві версії
розійшлися: GitHub Pages віддавав свіжу, а сервер — стару.

## Два деплої, один код

| Що | Адреса | Звідки | Що робить |
|---|---|---|---|
| GitHub Pages | https://meat-baron.kh.ua | корінь гілки `main` | сайт для клієнтів |
| Railway | https://api.meat-baron.kh.ua | той самий корінь через `server.js` | API, Telegram-бот, дзеркало сайту |

`server.js` роздає корінь репозиторію і ховає службові файли
(`server.js`, `package.json`, `data/`, `node_modules/`) — вони віддають 404.

У браузері адреса API задана в `index.html`:
```js
const API='https://api.meat-baron.kh.ua';
```
Абсолютна адреса потрібна, бо сайт і API живуть на різних доменах.
Стара адреса `meat-baron-production.up.railway.app` працює й далі —
на неї досі ходять сторінки з кешу браузера.

## Домен

`meat-baron.kh.ua` зареєстровано в NIC.UA, сервери імен теж NIC.UA
(`ns10–12.uadns.com`). Записи:

```
@                    A      185.199.108.153   ┐
@                    A      185.199.109.153   │ GitHub Pages
@                    A      185.199.110.153   │
@                    A      185.199.111.153   ┘
www                  CNAME  bogdanzimoglyad.github.io.
api                  CNAME  xjuas1uq.up.railway.app.
_railway-verify.api  TXT    railway-verify=…  (підтвердження для Railway)
```

Файл `CNAME` у корені репозиторію каже GitHub Pages, на якому домені
сайт. Без нього GitHub відповідає на домені 404. Старе посилання
`bogdanzimoglyad.github.io/meat-baron/` саме перенаправляє на домен.

На Railway у змінних проєкту стоїть `SITE_URL=https://meat-baron.kh.ua/`:
з неї бот будує кнопку «Стежити» в сповіщеннях.

**Сервери імен NIC.UA — окреме замовлення зі своїм терміном.** Домен
оплачено до 2028 року, а DNS-хостинг — до 13 грудня 2026, і без
продовження домен перестане відкриватися.

Вхід, кошик і останнє замовлення браузер зберігає окремо для кожного
домену: після переїзду всі, хто входив на github.io, входять заново.

## Запуск

1. Створити бота: у Telegram написати **@BotFather** → `/newbot` → скопіювати токен.

2. Придумати `BIND_CODE` — пароль, яким прив'язують чати до точок.
   Без нього команда `/bind` не працює взагалі. Так і задумано: інакше
   будь-хто додав би бота до себе в групу і забрав ваші замовлення.

3. Встановити і запустити:
```
npm install
BOT_TOKEN=ваш_токен BIND_CODE=ваш_пароль node server.js
```

4. Для кожної точки створити групу в Telegram, додати бота і операторів,
   у групі надіслати:
```
/points            — список точок
/bind 1 ваш_пароль — прив'язати чат до точки №1
/whoami            — перевірити прив'язку
```
   Повідомлення з паролем після цього краще видалити з чату.

5. Відкрити сайт: http://localhost:3000

## Вхід покупця

Номер не вводять руками і код нікуди не надсилають. Сайт просить у
сервера разовий ключ, відкриває бота за посиланням
`https://t.me/БОТ?start=КЛЮЧ`, людина тисне «Поділитися номером» — і
номер приходить від самого Telegram. Сайт у цей час опитує сервер і,
щойно номер підтверджено, отримує токен.

Так зроблено тому, що введений номер нічого не доводить: за ним можна
було б забрати чужу історію замовлень. Бот перевіряє ще й те, що
контакт належить самому відправнику — картку чужого контакту в Telegram
можна переслати.

Ключ входу живе 5 хвилин і лежить у памʼяті сервера. Токен живе 180
днів, зберігається в базі поруч із замовленнями і знімається кнопкою
«Вийти».

Імʼя бота сервер дізнається сам при старті. Якщо треба задати руками —
змінна оточення `BOT_USERNAME` (без «собачки»).

## Як працює
- Клієнт оформлює замовлення → воно летить у чат своєї точки
- Оператор тисне кнопки: Прийняти → Готується → Готове → Видано
- Сума на сайті орієнтовна. Поки замовлення «Нове» чи «Прийнято»,
  оператор міняє її лише кнопками під замовленням:
  «🧾 Фактична сума» — число з каси, де замовлення пробили й зважили;
  «➕ Додати» / «➖ Відняти» — якщо клієнт щось додав чи прибрав
  телефоном, відповідь «39 додали соус Ткемалі»; «💬 Коментар» — без
  зміни суми. Бот перепитує кожну зміну й показує різницю, а касову суму,
  що відрізняється більше ніж на 30%, позначає як можливу опечатку.
  З «Готується» кнопки зникають і сервер зміни відхиляє. Клієнт, що
  входив через Telegram, отримує повідомлення про кожну зміну; на сайті
  видно суму з сайту, кожну зміну окремим рядком і «До сплати»
- Сайт клієнта оновлює статус кожні 15 секунд
- Хто увійшов через Telegram — тому бот пише «прийнято» і «готове»
  просто в чат, із кнопкою «Стежити». Решті на статусі «Готове» піде
  SMS (поки що лише лог у консолі)

## PWA
Сайт встановлюється на телефон як застосунок:
- Android: зʼявляється банер «Додати на екран»
- iPhone: Safari → «Поділитися» → «На екран Додому»

Працює лише через HTTPS (на Railway/Render він увімкнений автоматично).

## Що треба доробити
- SMS для тих, хто не входив: підключити TurboSMS у функції `sendSms()`
  в `server.js`. Тим, хто увійшов, бот уже пише сам
- Онлайн-оплата: LiqPay або Fondy. Поки її немає, спосіб «карткою онлайн»
  прибрано з форми — інакше оператор бачив би «оплачено» без грошей
- Фото товарів замість заглушок
